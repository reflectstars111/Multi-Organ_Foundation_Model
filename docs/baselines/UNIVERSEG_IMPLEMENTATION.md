# UniverSeg-union-512-retrained 实现记录

更新：2026-10-13。使用官方 `JJGO/UniverSeg` 提交 `833a0c34c65e38d675e21bd48ddec6797cc03259`，不加载官方预训练分割权重。本文描述本项目统一协议适配，不声称复现原作者的全部预训练数据与增强配方。

## 网络与输入

`unet_moe/external_baselines/universeg.py` 包装官方 `UniverSeg(encoder_blocks=[64,64,64,64])`。查询输入 `[B,1,512,512]`、支持图像及二值掩膜各 `[B,8,1,512,512]`，输出并集 logits `[B,1,512,512]`。保留全部 CrossBlock、target/support interaction、skip、宽度及官方参数初始化。使用 activation checkpoint 降低激活显存，不改变计算图数学含义。

官方网络及 CrossConv 源文件的内容与本地上游副本完全一致。适配器与官方直接 forward 的输出、参数梯度逐元素一致；checkpoint 启用／关闭的输出及梯度也逐元素一致。`domain_ids` 用于公共调用接口，真正的任务条件由同域支持图像和掩膜提供。

## 支持集的标签完整性

腹部训练图包含未纳入并集的结构和 void 区域，因此没有可直接作为二值 support 的完整腹部整图。将 `-1` 改成背景会产生错误标注。本适配采用以下固定规则：

- 支持图像只来自训练集，同 query 数据域，排除同图及所有相同 `group` 的图像；每次无放回抽取 8 张。支持图像之间可以属于同一组，不能表述为 8 个独立患者。
- 标签完整且同时含前景／背景的图像保留完整视野。
- 部分标注图像在 512 统一并集标签网格上寻找最大面积的全已知矩形：短边至少 32 像素、含前景及已知背景，且保留该图原已标注前景至少 **25%**。约束在搜索时应用。面积并列时优先保留更多前景，再按左上坐标排序，保证确定性。
- 用 histogram 单调栈及前景积分图完成 O(HW) 搜索。矩形不满足条件时排除该候选。只有前景、其余全部未知的 AUL 样本不能形成有效支持。
- 图像和掩膜同时裁剪同一矩形，分别双线性／最近邻缩放至 512。裁剪前后都严格检查标签只含 0/1；不填充未知区，不伪造负像素。
- `support_manifest.json` 冻结每图索引、身份、ROI 坐标、面积、原／保留前景像素、前景保留比例及 ROI 掩膜 SHA-256。读取支持集时复核身份和标签。

这个适配改变支持图像视野，可能只包含部分器官并集；不能写成腹部支持仍是原完整图或保留全部前景。ROI 只应用于 support，**训练、验证、测试 query 始终保留原完整 512 图像和原 ignore 规则**。全空 query 仍参加训练；支持候选为了提供正负例，同时要求存在前景与已知背景。

MOFO 的先验预训练复用同一份训练 ROI 候选池；先验辅助项对全空或无已知背景的真值跳过。主分割目标依然保留这些 query。两方法都应披露先验／支持候选的筛选偏好。

## 隔离、随机性与预算

支持 manifest 构造只打开 train 的图像／标签；train、val、test 的 query 资格检查只读取清单元数据，验证每一个 query 在排除同图／同 group 后仍有至少 8 张支持，不会为了支持筛选读取测试像素。CAMUS 患者、CCA 体积、腹部 CT 来源等沿用已有 group；没有患者标识的图像数据集只能按可获得身份排除，不夸称已消除未知患者层面的关联。

已验证 train/val/test 的 **6737/1007/1618** 张 query 均满足该条件。最严格的腹部 train query 排除本 CT 来源后仍至少有 **390 张**支持候选（支持池本身来自 7 个训练 CT 来源）；跨 split 的检查只读取元数据。

训练支持抽样由独立固定种子 1729、训练 seed、epoch、query draw position、图像身份共同哈希决定，不依赖进程 RNG 或先前调用顺序，断点恢复可重建相同支持。验证／测试仅由固定种子和 query 身份决定，三个训练 seed、best/last 都使用相同支持选择。

S=8 意味着每个查询图像另外读取 8 张支持图像；这些曝光次数和计算量额外列出。主训练仍按照 Q04 的 4500 query/epoch、80 轮、有效 query batch16 计数，不能将支持读取隐藏到“与单输入模型等计算量”的描述中。

## 验证

`tests/test_external_support.py` 与 `tests/test_external_universeg.py` 合计 **11 项通过**，包括随机小网格穷举 ROI 最优性（尺寸、前景占比约束）、不合格 ROI 排除、图像/掩膜坐标配对、标签完整性、train-only 读取、全部 query 资格、同图／同组排除、无放回、无状态可恢复支持抽样、标签变更检测、官方网络／checkpoint 输出与梯度一致性。

```bash
.conda/bin/python -m pytest -q tests/test_external_support.py tests/test_external_universeg.py
```

另已在 Q04 独立环境完成真实腹部 train query＋冻结 ROI 支持池的 **512、S8、两次 CPU AdamW 更新**：物理/有效 query batch 均为 1，float32，2 CPU threads。两次损失为 1.39773、1.31670，耗时 22.63/21.17 秒，峰值进程 RSS 10.58 GiB；所有实际梯度有限，输出卷积参数每步确实更新。这只验证可训练性，不能当作性能改善结论。

证据位于 `runs/q04_preparation_20261013/verification/universeg/`（实际数据目录下）：`cpu_512_s8_two_updates.json`、`support_manifest.json`、`cpu_preflight.py`。该 CPU 功能检查不能代替有效 batch16、两次更新的正式 GPU gate。最终训练结果按 DSC (%)、HD95 (pixel)、ASSD (pixel) 统一输出。
